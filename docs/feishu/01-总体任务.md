---

## 0. 一句话目标

把全市场（A 股 / 美股 / 加密 / 预测市场）做成**统一市场数据 Facade**：对内按源适配，中间做规范化与领域能力，对外只暴露 **一套 REST `/v1` + 一套 MCP**。

仿真优先 · 无券商密钥 · 可 Docker Compose 一键拉起。

---

## 1. 要解决的问题

传统做法容易按「市场 × 功能 × 旧系统」切出一堆对外服务（`/ashare/quotes`、`/us/quotes`…），导致 Agent 工具爆炸、换源要改契约。

OmniAlpha 的原则：

| 原则 | 含义 |
|------|------|
| 市场是参数 | 符号前缀 `CN:` / `US:` / `CRYPTO:` / `POLY:`，不是四套 URL |
| 能力是模块 | 查 / 看 / 分析 / 选（+ Prediction 对象模型） |
| 旧系统只当供应商 | Adapter 挡在门外，对外名称不出现 vendor |
| 契约唯一 | HTTP OpenAPI 与 MCP 同一语义 |
| 网关/计费后挂 | APISIX、Lago 不进领域层 |

---

## 2. 六层架构（L0–L5）

```
调用方 ── HTTP /v1 ──┐
         MCP /mcp ───┤
                     ▼
              L4 Facade (FastAPI)
              L5 FastMCP（同进程投影）
                     ▼
     L3 领域：reference / marketdata / analytics / screener / prediction
                     ▼
     L2 事实：Postgres（字典）+ Redis（快照）[+ 以后 ClickHouse]
                     ▼
     L1 Adapters：cn_watch / us / crypto / polymarket / …
                     ▼
     L0 源系统：腾讯 / HiThink / Yahoo / OKX / Polymarket / …
```

| 层 | 名称 | 职责 | 不做什么 |
|---|---|---|---|
| **L0** | 源系统 | 现有看盘、分析、选股、交易所、Polymarket | 不再承担对外契约 |
| **L1** | Adapter | 鉴权、拉数、字段翻译、错误翻译、限频遵守 | 不对外；不算复杂指标 |
| **L2** | 规范化 | 统一标的 ID、时间、K 线、报价；字典/缓存/时序 | 不关心哪个 vendor |
| **L3** | 领域服务 | 查 / 看 / 分析 / 选 / Prediction 用例 | 不直接打 N 个旧 HTTP；不写计费 |
| **L4** | Facade | REST + OpenAPI + 鉴权入口 | 不写 vendor if/else |
| **L5** | MCP | 把 L3/L4 收成少量 tool 给 Agent | 不新增业务语义；不直连 L0 |

## 3. 市场 × 能力矩阵（目标形态）

用**标签**，不用矩阵微服务：

```
market:        CN | US | CRYPTO | POLY
capability:    watch | query | analyze | screen
```

| 能力 | 含义 | 典型路径 |
|------|------|----------|
| **watch（看）** | 实时快照、盘口、（以后）推送 | L1 → Redis → `get_quotes` |
| **query（查）** | 搜标的、资料、历史 K 线 | Postgres 字典 + 历史；不每次打看盘 |
| **analyze（分析）** | 指标 / 对比 / 因子 | 分析库或离线结果，不直打实时看盘 HTTP |
| **screen（选）** | 宇宙 + 过滤 + 排序 | Screener 领域；空实现不得伪装成功 |
| **prediction** | Event / Market / Outcome | 第二套对象，同一 L4/L5 门口 |

符号（第一天冻结）：

```
CN:600519
US:AAPL
CRYPTO:BTCUSDT
POLY:{market_id}
```

未知前缀 → **422**。

## 4. 第一期（phase1）vs 完整架构

| | **第一期（当前交付焦点）** | **完整架构再加** |
|-|-|-|
| 能力 | CN 查+看竖切：`instruments` / `quotes` / `bars` | analytics / screener 填实；Prediction 完整对象 |
| 市场 | CN（腾讯）为主；US/CRYPTO/POLY adapter 对齐中 | 四市场 watch/query 契约对齐 |
| 核心栈 | FastAPI + FastMCP + Postgres + Redis | — |
| 门口 | Facade 自管 API Key | **APISIX**（限流/审计） |
| 计费 | 结构化访问日志预留 | **Lago** |
| 时序 | bars 经 domain，存储可换 | **ClickHouse**（或 Timescale） |
| MCP | 三工具：`search_instruments` / `get_quotes` / `get_bars` | 随能力扩展，仍同源契约 |

路线图摘要：

| 阶段 | 内容 |
|------|------|
| **P1（当前）** | CN 查+看竖切；Compose；MCP 三工具；Eval 门禁 |
| **P2** | 美股 / 加密 / Polymarket 对齐同一 Quote/Bar（或 Prediction）契约 |
| **P3** | analytics / screener 填实 |
| **P4** | APISIX；可选 Lago；ClickHouse |

## 5. 对外契约（第一期）

```
GET /healthz
GET /v1/instruments
GET /v1/quotes?symbols=CN:600519,US:AAPL
GET /v1/bars?symbol=CN:600519&interval=1d&limit=5
```

MCP（`/mcp`）：`search_instruments` / `get_quotes` / `get_bars`  
规范化字段：`as_of`（UTC）、`source`、`stale`。
